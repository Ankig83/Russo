# Procedural geometry from a prompt (Blender / bpy)

## Когда применять
Пользователь описывает форму словами (например: "X-образная ножка, сечение
20x20мм, высота 450мм, лёгкая фаска по краям") и хочет получить её кодом —
это быстрее и легче править параметрами, чем лепить руками, особенно для
повторяющихся элементов (ножки, ряды заклёпок, молдинги, профили кромки).

## Порядок работы

1. **Разобрать промпт на параметры.** Явно выписать числовые параметры
   (размеры, количество повторов, радиусы скруглений) до написания кода —
   не зашивать их в код как магические числа без имён.

2. **Выбрать примитив генерации:**
   - Профильные/окантовочные элементы (кожаная окантовка, кромка) →
     Bezier curve + bevel object (уже используется в проекте для кожаной
     окантовки и ручек) — bpy: `bpy.data.curves.new(type='CURVE')`,
     `curve.bevel_object`.
   - Повторяющиеся элементы (заклёпки, декоративные накладки) → array
     modifier (`obj.modifiers.new(type='ARRAY')`) вместо ручного
     копирования объектов.
   - Сложные составные формы (X-ножки) → строить из простых примитивов
     (cube/cylinder) через bpy, склеивать через boolean/join, а не
     пытаться сделать одним mesh с нуля.

3. **Запускать headless, если объём большой** — через
   `blender --background --python script.py`, скрипт класть в `scripts/`
   (см. правило project-structure), не выполнять вручную в UI, если
   результат должен быть воспроизводим.

4. **Именование результата** — сгенерированный объект должен сразу получить
   финальное имя, совпадающее с тем, что ожидает R3F-код (см. правило
   glb-export-pipeline) — не оставлять `Cube.001` и т.п.

5. **Параметры — как переменные в начале скрипта**, не как захардкоженные
   числа внутри вызовов bpy. Это позволяет быстро подправить размеры по
   фидбеку без пересборки логики.

6. **Проверка результата** — после генерации явно предложить сделать
   рендер/скриншот объекта для сверки с промптом, до того как встраивать
   его в общую сцену шкафа.

```python
# --- параметры (единственное место для правок) ---
LEG_HEIGHT = 0.45      # м
SECTION_SIZE = 0.02    # м, сечение бруса
BEVEL_WIDTH = 0.002    # м, фаска

def build_x_leg():
    # ... генерация геометрии из параметров выше
    pass

if __name__ == "__main__":
    build_x_leg()
```

## Частые ошибки
- Захардкоженные размеры вперемешку с логикой — сложно менять по фидбеку.
- Генерация без финального имени объекта — потом расхождение с R3F-кодом.
- Слишком сложная геометрия одним mesh вместо модификаторов (array/bevel) —
  тяжелее редактировать и хуже держит топологию для дальнейшего экспорта.
